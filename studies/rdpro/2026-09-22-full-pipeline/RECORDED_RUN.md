# Recorded RDPro five-condition run

The user requested execution after verifying the official Bitbucket source and republishing the preparation. This invocation uses the existing 16-API, 32-task bank, three audience trials and five conditions: 480 units. Initial code plus at most one repair is allowed for every unit. The separate three-README-policy comparison is deferred.

## Records retained

For each README entry, alias/hint batch and audience attempt, the recording contract retains exact model input text and system prompt, requested/effective settings, controller/source/prompt fingerprints, provider response identifiers and available response messages, generated text/code, timestamps and elapsed durations. Usage records distinguish input, cached input, output and reasoning tokens; reasoning tokens are included in output, not charged twice. Unknown usage remains unknown.

Each audience task/trial/condition retains initial and repair rounds separately, including provider-attempt history, compile/run commands, return codes, stdout/stderr, per-fixture checker outcomes, required-method traces, alias events, hint matching/delivery, documentation selection/truncation and final verdict. Original error evidence remains available beside conservative error classifications; classifications do not claim that documentation caused a failure.

Local telemetry indexes link task rows to exact evidence and aggregate known cost/time/tokens while reporting missing usage and unresolved reservations. Private fixtures, expected answers, trusted reference programs and machine-bound raw execution evidence are retained locally and excluded from experimental model requests and this public preparation package. Credentials are not logged. Hidden internal model reasoning text is not exposed by the API; its reported token count is recorded when available.

## Execution stages and limits

The plan prepares fresh sessions after recording/prompt corrections; runs four alias/hint proposal batches and 280 README author entries; performs one deep dive/rewrite pair on four preselected README entries; bundles and installs matched treatment bytes; builds source-bound runtimes; checks alias behavior and hint delivery; validates trusted controls for all conditions; freezes exact inputs; then runs the 480 audience units and exports a final report.

The model remains GPT-5.3-Codex with low reasoning and standard service tier. The shared $100 guard stops further reservations before its cap would be exceeded; estimated main-study spend is $19–$26, with a roughly $55 high-output scenario. Stopping on invalid evidence or uncertain provider calls preserves partial results rather than manufacturing completion.

Measured historical audience calls averaged 6.95 seconds. The broader-bank local checker controls averaged 15.47 seconds. Five-condition control validation alone involves 480 program checks; audience evaluation is estimated at 708 calls/checks using the pilot repair rate. Full README-author timing has not yet been measured for this scope. A planning estimate is **8–12 hours after preparation**, with **up to 24 hours** under slow generation or high repair rates. This is a scenario estimate, not a guaranteed finish time. Progress must be calculated from saved phase states, not elapsed wall time alone.

At this preparation publication, new model outputs and audience results do not yet exist. A successful source audit, generated document or installed proposal is not a benchmark success result.
