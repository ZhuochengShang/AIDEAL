# Defining API inventory

Enable this reader explicitly with `codebase.identity_mode: qualified` and an API inventory whose `kind` is `qualified_source_api_inventory`, `schema` is 2. Existing manifests retain their existing reader and selection policies.

The manifest binds `source_version`, `source_commit`, `source_tree`, `source_root`, `source_inventory` plus its SHA256, all candidate `declaration_ids` for one language, and a canonical selection receipt plus SHA256. `canonical_declaration_ids` and `api_ids` contain the selected exact definitions. The selection policy is `owner_qualified_max_arity_v2`: different defining owners remain distinct; overload comparison applies within a qualified API. Scala compiler-proven companion collisions have explicit owner-kind identity metadata. A call to another API does not itself prove a redundant wrapper.

`source_root` is relative to the config root. JSON evidence locators can be rebased by the launcher, but their payload hashes remain bound. Configure `codebase.api_origin.source_roots` under that same source root and use the exact frozen logical namespace policy. The reader verifies pinned Git HEAD/tree, tracked cleanliness, every bound source file, declaration spans, source-root/namespace policy and selected identities. Ownership is recomputed at the relocated root; old absolute-machine ownership hashes are not substituted as current observations.

Python uses static AST parsing. MDAnalysis `.pyx` verification requires operator tooling **Cython==3.3.1** (Requires-Python >=3.9), without importing the subject library. First access independently verifies source-derived selection facts. The parser cache is keyed by current source hashes, package roots, pinned snapshot, scanner hash, parser version and runtime binding facts. Source bytes are still checked before every cache reuse. JVM inventories use the existing compiler-backed declaration evidence, retained in `compiler-inventory.json`; this reader does not launch Java/Scala or claim to recompile them.

Rows keep `name`, defining `qualified_name`, qualified `api_id`, `site_id`, source file/span hashes, parameters, constructor arity status and source scope. Public reexports/inherited paths are separate exposure edges and map to the same defining API. `public_access_paths`, `preferred_public_path`, `exposure_ids` and `public_exposure_established` preserve callable access without inventing a new implementation. Properties and C-only Cython helpers remain visible but are not callable execution targets. External imports are not relabeled as owned definitions.

A singleton constructor with unknown arity remains explicitly `None`; it is never changed to zero. Unresolved dynamic exports, generated attributes and external base members remain in the ledger's issues/exposures. Zero unresolved **selection families** therefore does not imply that every dynamic Python attribute was statically enumerated. Conditional variants require source clauses plus hash-bound recorded runtime facts; inactive variants remain explicit ledger rows.

The supplied `CODEBASE_CONFIG.json` per library gives the effective origin policy and required config-root evidence copies. In particular, tslearn's recorded torch availability must be copied to `inputs/runtime-binding-evidence.json` under its config root. Beast's namespace policy includes both `edu.ucr.cs.bdlab` and the custom `org.apache.spark.beast`, which overrides the broader external `org.apache.spark` prefix by most-specific match. The 47 test-support declaration records remain visible and are excluded; five production spatialtest callables remain included.

SQL retains its registered-SQL reader and source-validated aliases. Its names are registered logical SQL operations, not Rust factory methods. Do not infer SQL arity from factory parameters, or treat a documentation file as a defining implementation. `registration-origin.json` separately records owned source registrations/adapters and any unresolved dynamic dependency boundary.

Original documentation is separately bound through `files.original_doc_manifest` plus SHA256. The manifest maps exact API IDs to documented/undocumented/unresolved decisions. Full qualified identities and statically resolved exposure aliases receive coverage credit; bare words do not. A pinned root README is shared context for every target without increasing per-API coverage. Rendered API-page corpora are not labeled as the entire documentation website. No implementation source is silently appended to original prose.
